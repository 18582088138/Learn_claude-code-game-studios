# 围绕类幸存者游戏的学习路线

[返回索引](README.md) · [官方章节对照](02-official-tutorials.md) · [验收清单](03-practice-checklist.md)

## 学习目标

不是把所有代码都背下来，而是能理解 AI 修改了什么、定位问题、调整参数，并把游戏运行与导出。

以下学习顺序和范围是针对你的项目提出的建议，并非官方课程安排或完成时间承诺。

## 第一阶段：玩家能移动

**阅读**：节点与场景、创建实例、第一个脚本、玩家输入；按需查 CharacterBody2D、Camera2D。

**实现**：一个玩家场景、一张简单地图、WASD/方向键移动、摄像机跟随。先用几何图形或占位图片。

**要理解**：场景可以作为可复用实体；节点构成场景；实例是场景运行时的对象。理解 `_process` 与 `_physics_process` 的用途。`CharacterBody2D.velocity` 表示速度，使用 `move_and_slide()` 时不要再次把它乘以 delta；其他手动按速度移动的位置更新需要考虑时间步长，具体见对应 API。

**小练习**：自己修改速度；比较斜向和横向移动；解释为什么斜向输入通常要限制向量长度。

**验收**：八方向移动合理；窗口尺寸变化后能看到玩家；无持续错误日志。

## 第二阶段：敌人追击与接触伤害

**阅读**：实例化、信号、物理简介、Area2D、Timer；对照官方 2D 教程的“创建敌人”“主场景”。

**实现**：一种敌人，定时从玩家周围生成并追击；接触玩家扣血，玩家有短暂无敌时间。

**要理解**：碰撞 layer 表示自己在哪些层，mask 表示关注哪些层；检测区域和实体运动碰撞用途不同。生成、销毁和场景引用有生命周期。

**小练习**：画出玩家、敌人、子弹、拾取物的碰撞表；把敌人出生位置从固定点改成玩家附近的环形范围。

**验收**：扣血频率可控；敌人不会意外出生在玩家身上；玩家死亡后停止战斗。第一张空地图可以先用直接追击，有障碍地图时再研究导航。

## 第三阶段：自动攻击

**阅读**：Timer、Area2D、资源、GDScript 基础。官方 Dodge the Creeps 没有完整的自动攻击系统，本阶段是基于官方概念的项目练习。

**实现**：一种自动攻击武器，选择攻击目标，生成子弹、造成伤害、击杀敌人。没有目标时的行为要明确。

**要理解**：攻击冷却、伤害、速度、射程属于配置；实际运行状态属于当前实体或系统。子弹命中、超时和离开有效范围后的清理必须有定义。

**小练习**：调整攻击间隔与伤害，比较“高频低伤”和“低频高伤”；让子弹不会伤到玩家。

**验收**：目标选择符合预期；敌人只结算一次死亡；子弹不会无限积累。

## 第四阶段：经验与升级

**阅读**：信号、资源、GUI 布局、容器；对照官方 2D 教程的 HUD。

**实现**：敌人死亡掉落经验，玩家接近后拾取；经验达到阈值时暂停并显示三选一升级；选择后继续。

**要理解**：用信号传递“死亡”“经验变化”等事件；UI 展示状态，避免各处直接相互修改。升级数据与 UI 布局分开。暂停时升级 UI 仍需能接收输入，应检查节点的 process mode。

**小练习**：做伤害、攻击速度、移动速度三个升级；检查经验一次跨过多个等级时的处理。

**验收**：经验只拾取一次；暂停期间战斗停止且 UI 可操作；升级效果真实生效；不存在没有可选升级的卡死状态。

## 第五阶段：完整一局

**阅读**：官方 2D 教程的 HUD、收尾；按需查资源与存档。

**实现**：开始、游玩、暂停、失败或通关、结算、重开；一局 5 分钟，基本音效和战斗反馈。

**建议范围**：一个角色、一张地图、两种敌人、两种武器、六个升级选项。先完成闭环，再增加内容。

**小练习**：连续重开三次；检查敌人、计时器、经验、武器等级和 UI 是否恢复初始状态。

**验收**：不进入编辑器也能完成一局并重新开始；玩法节奏有变化；别人能理解如何操作。

## 第六阶段：PC 与手机

**阅读**：多分辨率、触屏输入类参考、Windows 导出、目标手机平台导出；按需查分析器。

**实现**：键盘与虚拟摇杆输出统一的移动向量；适配横屏 HUD、触屏升级选项；导出 Windows 和目标手机版本。

`TouchScreenButton` 适合触屏按钮，本身不等于模拟摇杆。模拟摇杆可用 ScreenTouch/ScreenDrag 处理触点，转换成方向和力度。多点触控时要记录触点 id，防止点升级按钮时影响摇杆。

**节奏建议**：第二或第三阶段就做一次手机导出验证，后续持续真机测试。第六阶段完成全面适配，不要到最后才第一次尝试手机运行。

**验收**：真实设备上的移动、升级、重开可操作；按钮够大；宽高比不同仍能看清信息；切后台与返回时行为合理。

## 性能学习时机

有了基本战斗后再学习分析器。逐步增加敌人、子弹和经验掉落，记录测试设备、峰值数量、帧率和瓶颈。

不要把“节点多”直接当成“必须 ECS”或“必须对象池”。先测量 CPU、物理、渲染和内存，再决定是否减少检测频率、调整碰撞、批量绘制或复用对象。对象池也会引入状态重置问题。

## 如何对照官方完整示例

官方 Dodge the Creeps 包含移动、敌人生成、计分、HUD、失败和重开，适合学习组织方式。你可以先运行完成版，再逐章读代码；无需先一字不差复制全套。

它不包含你的完整武器、经验、升级与手机摇杆系统。使用相应官方概念独立扩展，避免把官方示例当成类幸存者成品框架。

## 给 DSH 的学习任务模板

```text
当前项目：Godot 4.x，GDScript，2D 单机类幸存者。
当前学习阶段：[填写阶段]
这次仅实现：[填写一个可试玩的功能]

先检查项目和安装的 Godot 版本，对照相同版本官方文档。
列出涉及的节点、场景、信号、资源和对应官方章节。
用我已有编程经验能理解的方式解释这些概念。
实现后告诉我如何运行、如何调整一个关键参数、如何验证边界情况。
记录实际运行结果；没有运行就明确标注未验证。
结尾给我一个需要自己动手的小练习。
```
